# 持仓模块重构说明

日期：2026-11-02。用户确认「剩余金额」是目前还持有的基金市值。

## 本轮实现

- 持仓首页合并金额总览和基金列表，以持仓市值为主，持有盈亏、当日变动为次，剩余成本作为辅助信息。
- 唯一主动作「记一笔」打开买入表单；只保留基金、买入金额、交易日期、提交时段，备注折叠。默认日期与净值确认提示来自服务器交易日历。
- 首次使用提供「记录第一笔」和「导入历史记录」，不向真实账户写入示例持仓。保存买入后回到持仓页。
- 交易记录、复核与提醒、导入与对账保留为次级入口；清仓后仍能查看交易记录。
- 基金行默认展示市值、持有盈亏、当日变动；展开后查看分笔、净值历史以及校正、减仓、分红、份额调整和删除。
- 排序集中在一个选择框，高级筛选折叠。移除金额列表的延迟入场动画。
- 保留经典、深色、cyber 主题和现有字体/图标；金额使用等宽数字，主要控件至少 44px。

## 金额与统计合同

| 名称 | 含义与边界 |
| --- | --- |
| 持仓市值 | 仍持有的确认份额 × 所选口径净值，不是可用现金 |
| 持有盈亏 | 同一已计价范围的市值减剩余成本，不包括已卖出盈亏和现金分红 |
| 当日变动 | 当前持仓在对应净值日的市值变化，不是按实际买卖时点结算的账户损益 |
| 剩余成本 | 当前持仓对应的成本本金，即既有接口的 amount |
| 部分覆盖 | 明示已计价笔数、待确认/待更新笔数；使用相同范围的成本计算盈亏 |

`holding-display.ts` 统一金额显示、排序、筛选的选择逻辑。官方数据不可用时显示 `--`，不静默切到预估。官方部分小计依据 `real_metrics_ready_count` 保留，不能因为全量未就绪而丢弃有效小计。盘中变动按确认份额乘净值差计算，不再用成本乘涨跌幅冒充持仓收益。

买入继续使用原有 `{fund_id, amount, trade_at, note}` 合同，不新增数据库迁移。已有持仓的当前市值不能直接当作买入成本；应导入真实买入记录，再核对确认份额。当前接口不支持原子录入完整外部账户期初余额。

减仓优先填写份额，系统按比例减少成本。金额字段明确为「减少成本本金（非到账金额）」，与份额互斥输入。真实赎回到账、费用、已实现收益和可用余额需要独立的后端账本设计，本轮没有伪造这些字段。

## 验证与限制

- 本地验收：前端回归 125 项通过，包含 SEO/SSR 既有回归；全项目 ESLint、TypeScript 检查、Next.js 生产构建及 git diff --check 通过。构建与 SSR 测试使用本地 fixture，不能将此测试产物直接部署为生产版本。
- 新增 selectors 回归：份额算法与排序一致、部分官方覆盖、零官方覆盖、不使用成本 fallback、同基金未确认分笔、缺失/非有限数字和零收益。
- 页面测试拦截全部 `/api/v1/**` 请求，覆盖首次买入、加载、失败、部分计价、官方/预估切换、交易操作入口和三主题手机布局。
- 所有测试写入都在隔离 mock 中，不对生产账户试写。
- 视觉截图包含桌面 1440px、手机 360/390px；按金额层级、可读性、触控和无横向溢出验收，不把无设计稿的重构宣称为像素级还原。
- 数据日期与覆盖依赖上游有效信息；估值是参考数据。真实累计收益、赎回到账与费用仍属于后续账本工作。
- 记录意愿是否改善还需要上线后的任务成功率、填表时间和用户访谈验证，不能由代码测试直接证明。
