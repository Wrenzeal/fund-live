# 基金观察

入口为顶栏“观察”，路径 `/observations`。选择基金后进入 `/observations/[fundId]`，查看基金、目标 ETF 及部分已披露重仓股的近期公告与披露资料。

## 分工

| 页面 | 职责 |
| --- | --- |
| 首页 | 实时估值、分时、官方净值、持仓归因及行业主题 |
| 自选 | 用户分组和跟踪基金 |
| 持仓 | 资产、收益、流水、集中度、对账及数据待补齐 |
| 基金观察 | 真实公告标题、发布日期、来源原文、持仓报告期和披露覆盖 |
| 研究 | 市场行情、技术指标、公式及事件研究 |

观察页不输出综合评分、推荐比例、投资优劣排名或标题情感判断；不重复估值和净值图表。最近查看复用浏览器已有搜索记录，不新增一套自选管理。

## 数据与边界

- 独立接口 `GET /api/v1/fund/:id/observation`，不构建旧 V4 评分，不读取持久化量化事件历史。
- 公告仅保留最近 45 日的有效发布日期，去重后按发布日期倒序。显示完整来源标题；来源存在不代表内容已核实，更不代表利好或利空。
- 基金公告读取公开分类的近期列表；重仓股公告只覆盖部分沪深持仓。结果是有限范围的披露列表，不是全量新闻搜索。
- 缺少持仓时基金公告仍独立读取。目标 ETF 持仓会明确标注来源，其覆盖不代表联接基金实时权益仓位。
- 持仓报告期距今天数与公告发布时间分别显示，不把服务器检查时间当成公告时间，不将资料完整度转换为预测可信度。
- 来源状态区分成功、部分可用、暂不可用和未覆盖。请求失败不能显示成“没有公告”；单源失败不隐藏其他来源。
- 前端按低频刷新公告；切换基金不复用上一只基金的数据。没有后台交易、通知发送或自动买卖行为。

## 兼容和发布

旧 `/analysis/rankings` 跳转至观察入口，旧 `/analysis/[fundId]` 跳转至对应观察详情。旧分析/Lean API、实验档案和数据库保留兼容；正式页面不再请求评分，原夜间评分批量刷新不再随 API 自动启动。手工实验工具仍可运行。

发布需要同时更新 Go API 与前端，因为观察使用新增接口；仅重新部署 Vercel 不会为旧后端增加该接口。不需要新增数据库表或迁移，不删除旧记录。

本地检查包括 Go 测试/vet、前端 lint/类型/生产构建，以及公告日期过滤、重复项、来源失败、切换基金、旧链接跳转和手机布局回归。真实上游可用性以部署后的状态为准。
