# FundLive 2.0 设计提案

2026-11-03。状态：用户已批准 A「纸白松绿」，基础设计系统与基金持仓结构已在本地实现，尚未上线。可打开同目录 `fundlive-2-concept.html` 比较三个方案；概念页不连接 API，所有名称和金额为示意。

## 判断

持仓分类值得重构，但重点是把基金类型、行业、主题、人工标注拆清楚。全站精致程度受信息层级、密度、控件一致性与配色共同影响，单纯换背景色不会解决。

当前页面的四个问题有直接代码依据：

| 问题 | 证据 | 设计后果 |
| --- | --- | --- |
| 「持仓分类」同时承载基金类型、主板块、主主题、人工标签、自动权重和覆盖提示 | `web/src/components/fund-sector-card.tsx` | 用户难以区分基金身份、客观披露和人工解释 |
| 行业与主题分别套面板、主标签块、Top 行卡片；两种颜色平行竞争 | 同组件 `ClassificationModule` | 面积大，权重比较却不直观 |
| 三主题有不少组件硬编码 cyan / fuchsia / emerald，靠全局覆盖适配浅色 | 分类组件及 `web/src/app/globals.css` | 主题色、状态色和涨跌色职责不清，局部对比度难维护 |
| 玻璃、光晕、渐变、较大圆角和阴影同时存在 | `brand-mark.tsx`、`.glass`、主题背景、各页面 Surface | 视觉强调过多，缺少安静的基础层 |

这是源代码和已验收截图的审查，不是用户研究结果。是否提升记录意愿仍需实际任务测试。

## 持仓分类的信息结构

建议模块名改为「基金持仓结构」，回答：这只基金的已披露资金主要投向哪里？避免让用户误以为这是个人账户的资产配置。

1. 基金类型放回基金标题旁，不与行业权重混成「主分类」。
2. 「行业分布」为默认视图：最多三至五条水平条形，名称、比例对齐；条形使用一致的 0–100% 基准，不能把 Top 3 归一成整只基金。
3. 「相关主题」为第二视角：先显示主题名称，权重计算解释按需展开。
4. 「人工标注」单独呈现，明确与自动判断的差别；保留管理员编辑权限，普通用户只读。
5. 披露期、来源、权重分母随对应数据一起展示；行业和主题快照日期可能不同，不能合并成一个更新日期冒充一致。
6. 覆盖不足、来源失败、暂未归类要有不同状态。缺少足够元数据时不臆测「全仓覆盖率」。

### 数据边界

- 当前行业权重是对提供的披露持仓 `HoldingRatio` 汇总，后端快照只返回前三项。不能用这三项倒算「其他仓位」或全部映射比例。
- 当前主题权重对同一股票的多个主题均分。主题分布属于映射结果，不是基金公司披露的官方主题仓位，也不能与行业比例相加。
- `confidence` 基于已映射比例生成等级，不是预测准确率，不能改画为「AI 置信度 92%」。
- 目标 ETF、QDII、直接披露的来源要分别说明。没有正确换算时不能把目标 ETF 权重称为联接基金净资产权重。
- 已有快照足以先做 UI 重构；若需要完整行业分布、完整覆盖率与来源内穿透细节，再单独扩充 API 元数据与回归。

## 三套视觉方向

| | A 纸白松绿，推荐 | B 石墨蓝灰 | C 瓷白靛蓝 |
| --- | --- | --- | --- |
| 场景 | 日常查看基金、持仓记账 | 晚间研究、较高密度桌面 | 手机快速浏览、轻量个人账户 |
| 底色 / 表面 | `#F3F5F2` / `#FFFFFF` | `#13181C` / `#1B2227` | `#F4F5F9` / `#FFFFFF` |
| 正文 / 强调 | `#202B26` / `#285D49` | `#EDF1F3` / `#A2C5DC` | `#252B40` / `#505E94` |
| 组成 | 稳定的自选侧栏，内容为主，少量轻边界 | 较紧凑栏宽，边界清楚，数字排布更紧凑 | 取消桌面侧栏，居中内容，较宽松触控 |
| 取舍 | 易读、辨识稳定；不做金色奢华装饰 | 显示器/环境差异更影响可读性 | 亲近易用，但研究信息要避免过度稀疏 |

推荐 A 作为默认视觉方向，B 为相应的深色方案候选。最终应是同一套组件、间距和数据语义，不能让浅深主题变成两套不同产品。概念中的 A/B/C 是方向比较，不建议上线三个独立组件系统。

行业条形使用单一强调色的深浅变化；红绿专门表示涨跌，颜色之外始终保留正负号。品牌松绿不用于收益标签。正文与辅助文字验收对比度分别满足可读性要求，不以「淡」代替层级。

## 全站设计系统

- 结构靠对齐、留白与表面层次建立，去掉常驻发光、全屏径向光斑和大部分磨砂背景；只在必要的浮层用阴影。
- 只保留一组主强调色。选中状态、主动作使用强调色；警告、涨跌和错误用独立语义色。
- 保留现有中文无衬线字体，先统一字重、行距、数字等宽。常规正文 14–16px，关键数字 32–40px，核心金融日期与说明不能只用极淡小字。
- 建立小而统一的圆角尺度：控件约 6–8px，面板约 12px，浮层约 16px。表格行、行业条目不各自套卡片。
- 全站按钮、输入、选择框、标签、错误提示共用语义 token 与既有组件。清理逐组件硬编码颜色及主题补丁，不再加覆盖补丁叠层。
- 数据先出现，动画只表达切换和反馈。读金额、净值、分类不等待滚动入场。
- 手机重排信息而不是机械纵向堆叠桌面列；44px 触控区、键盘可用、焦点可见；200% 文本放大、慢请求和长基金名纳入验收。
- Logo 可先保留原有轮廓，减弱光晕与渐变；是否重做标识是独立品牌决策。

## 执行顺序与验收

1. 先在「基金持仓结构」完整落地选定方向：保留原数据、权限、管理员编辑、来源与缺失状态，补测试。
2. 以首页和持仓页作为两种密度样板，统一导航、Typography、Button、Surface、Input 和主题 token。
3. 同一规范覆盖自选、基金观察、研究、登录。导航职责和后端记账合同不变，不把重设计扩成新分析系统。
4. 逐页做桌面/手机、浅/深色和可访问性检查，再清理老样式；完成后按实际实现更新 DESIGN.md。

成功标准：用户能迅速复述「哪只基金、什么披露期、主要行业、比例属于什么口径」；看得出人工标注；关键数字不被彩色装饰抢走；新旧页面一致。概念页不证明线上数据正确，也不能直接替代真实 API 验收。
