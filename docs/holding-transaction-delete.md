# 删除持仓流水

删除功能引入版本：`2026.11.03-holding-transaction-delete`。当前升级包还包含期初持仓功能，请同时阅读 `holding-opening-and-valuation.md` 并先执行对应增量 SQL。

## 使用方式

- 持仓 → 交易记录 → 对应记录的「删除流水」。
- 流水详情页右上方也提供同一入口；删除后返回交易记录。
- 确认框显示基金、金额、北京时间记录日期，并明确说明：只删除历史记录，当前持仓成本与份额不变。
- 正常和已作废流水都能删除。取消/Escape 不发送请求；请求期间禁用重复提交，失败保留记录与确认框供重试。
- 删除后清理各筛选分页缓存和详情缓存；后台刷新失败不会把已成功的删除误报为失败。

## 接口与数据边界

`DELETE /api/v1/user/holdings/transactions/:transactionId`

使用已有登录鉴权和账号范围。未登录返回 401，不存在或属于其他账号的记录返回 404；成功返回 `{"success":true,"data":{"deleted":true}}`。

从数据库真正删除选定行，不把作废重命名为删除，也不新建一条可见的「删除流水」活动。原有 `type=delete` 表示删除当前持仓时产生的活动，与本接口删除历史记录不同。

删除后无法通过应用恢复；它不撤销买卖、分红或份额调整对当前持仓的影响。需要撤销交易影响时仍应使用回滚预览/自动冲正或持仓校正。

数据库在一次事务中删除目标行，并在同一账号、同一关联持仓的前序流水中记录最小的交易链缺失标记（沿用 metadata 字段）。这防止删除后续记录后，系统错误认定旧流水可安全冲正。人工校正能力保留；不会把其他账号、其他持仓或后续记录一并删除。

当前 API 实例内的删除、作废和冲正会串行执行，避免同一记录被删除与冲正同时消费。未扩大为全系统多实例的分布式记账锁。

无需数据库迁移或重新导入空库 SQL。
